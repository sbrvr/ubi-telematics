# Meridian Mutual UBI: same-week driving risk, explainable disputes in under a day
Working Databricks prototype: Lakeflow -> Unity Catalog -> Lakebase -> ML + GenAI -> Genie -> App. Proof: evidence/ (generated by the job).

**Anchor:** Insurance Outcome Map -> Product Innovation -> Usage-based insurance (Drive Growth; also Underwriting & Actuarial).

**Customer:** Meridian Mutual (fictional), US personal auto, ~$600M written premium, 400k policies, 60k UBI vehicles, Austin TX.
**Problem:** a vendor black-box score arrives monthly and 30-45 days late, so good drivers wait a term for a discount and churn;
underwriters can't explain it, so a dispute takes ~5 days and usually ends in a blanket concession; actuarial can't file it.

**Outcome (base case, VALUE_MODEL.md):** ~**$2.7M/yr profit impact net of ~$10k/yr measured, scaled platform cost, plus $9M new
earned premium.** UBI enrollment 15% -> 18%, UBI loss ratio -2 pts ($1.8M), disputes ~5 days -> < 1 day ($0.4M).
**It ran:** 53.5M GPS points with every injected defect caught (evidence/run_log.md); telematics Gini lift +0.20, 95% CI
0.07-0.34 (evidence/model_and_governance.md); 2.58 ms Lakebase reads, Genie 12/12 (evidence/lakebase_genie_app.md).

## Golden thread: driver D-0427 (evidence/journey.md)
D-0427 disputes the 27 Oct trip ("my passenger was using my phone"): raw drop file -> bronze -> trip (903 points, 15.3 mi,
110 s speeding) -> decile 8, +14.1%, "Phone handling 16.4x peer median" -> Lakebase -> AI draft (escalate, prompt hash
logged) -> override to +4% under four eyes (demo flag labelled) -> Genie: "which overrides were approved this week?" -> lineage.

## Architecture
```
generator (seeded, real OSM roads) -> UC Volume hourly JSON drops
Lakeflow SDP: bronze (Auto Loader, _corrupt) -> silver (dedupe on arrival watermark, skew fix, quarantine, H3 + ST_ map-match,
  trips, events) -> gold (consented 30-day features, KPIs)     UC: GPS mask, state row filter, class.location tags, lineage
train_score: XGBoost Poisson -> filed GLM relativities (isotonic, non-decreasing, -30%..+15%) -> SHAP reason codes -> gold_driver_scores (CDF)
Lakebase Autoscaling: synced scores (TRIGGERED) + features (SNAPSHOT) | native disputes, overrides (four eyes), audit_log
Genie space over gold + live Lakebase | Streamlit app (SQL on behalf of the user) | job ubi_end_to_end runs it all + evidence
```
Pricing changes apply at renewal only through the filed plan; the policy admin system stays the system of record.

## How to run
```
databricks bundle deploy                 # pipeline, job, app
databricks bundle run ubi_end_to_end     # generate -> pipeline -> rescore -> sync -> Lakebase -> Genie bench -> evidence
databricks bundle run ubi_app            # (re)start the app; deploy alone does not restart it
```
Workspace IDs are `<placeholders>`: set yours before deploying (catalog `surajb` is the author's).
Promotion: `src/train_score.py` mode=promote version=N approver=<name> (training only sets @challenger).
Prereqs: catalog `surajb`; `src/governance.sql` before the first pipeline update; `src/lakebase_setup.py` and
`src/genie_setup.py` create the Lakebase project and Genie space.

## Scale limits
- The generator is a single job: fine for 1k vehicles, not a load test for 60k.
- Map-matching is nearest-segment (H3 + ST_Distance); dense intersections and parallel roads need HMM (Valhalla/OSRM).
- The lift is synthetic by construction and noisy: re-drawing the ~120 claims 20x gives median +0.105 (CI > 0 in 8/20).
  Folds follow Spark row order, so +0.201 isn't bit-reproducible (fix staged for the pilot). The parallel run decides.
- Lakebase holds driver-level rows only (scores, features, disputes); GPS stays in the lakehouse.
